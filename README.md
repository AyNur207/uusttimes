# The UUST Times

Студенческое издание УУНиТ на Flask + Jinja2: аккаунты, новости, обложки, пагинация, модерация и поддержка разработчиков. Приложение находится в корне репозитория. Сам сайт доступен по ссылке https://uust-times.onrender.com/

Ссылка на репозиторий https://github.com/AyNur207/uusttimes.git

Короткий сценарий проверки:

1. Откройте главную страницу, выберите категорию и перейдите между страницами ленты.
2. Зарегистрируйте обычного пользователя в отдельном браузере или окне инкогнито. Предложите тестовую новость и проверьте статус в «Моих новостях».
3. Войдите в демонстрационный аккаунт администратора. В «Модерации» одобрите заявку или отклоните её с указанием причины. Одобренная новость появится в общей ленте.
4. На опубликованной новости выберите реакцию, замените её другой и снимите повторным нажатием.
5. От имени администратора опубликуйте собственную тестовую новость: она появится сразу. Затем откройте её, раскройте «Удалить новость» и подтвердите удаление.

## Локальный запуск

На Render используется Python 3.11.9 из `.python-version`. Локально подойдёт Python 3.11 или новее.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:8080. Вариант с автоматическим перезапуском для разработки:

```powershell
.\.venv\Scripts\python.exe -m flask --app app run --debug --port 8080
```

Скопируйте `.env.example` в `.env` на новом компьютере и заполните нужные настройки. Существующий `.env` не перезаписывайте. Файл читается автоматически при создании приложения; после изменения перезапустите сервер. Переменные окружения имеют приоритет над `.env`, явная тестовая конфигурация — над обоими источниками.

## Пользователи и публикация

- Гость читает опубликованные новости и может зарегистрироваться или войти.
- Пользователь `member` отправляет материал на проверку. Новость получает `pending` и видна только автору и администраторам.
- Администратор `admin` проверяет очередь: публикует (`published`) или отклоняет (`rejected`) с обязательной причиной.
- Свои новости администратор публикует сразу. В записи сохраняются автор, проверяющий и время публикации; дополнительное одобрение не требуется.
- На странице опубликованной новости администратору доступно «Удалить новость»: раскройте блок, отметьте подтверждение и нажмите кнопку удаления. Удалить можно свою или чужую публикацию. Автор без прав администратора удалить её не может.
- «Мои новости» привязаны к аккаунту, работают в разных браузерах после входа и показывают статус и причину отклонения.
- Изменение ролей через форму регистрации или отправку новости невозможно: роль нового аккаунта всегда `member`, автора и статус назначает сервер.

Первого администратора можно создать или назначить существующему аккаунту:

```powershell
.\.venv\Scripts\python.exe -m flask --app app create-admin admin@example.com
```

Эту команду выполняет владелец проекта в терминале с доступом к нужной БД. Для опубликованного сайта её запускают на сервере; локальный запуск обычно меняет только локальную базу. Регистрация на сайте создаёт обычного пользователя и не позволяет самостоятельно получить права администратора. `admin@example.com` здесь — пример email для команды назначения прав.

Для нового аккаунта команда запросит пароль без вывода на экран. Существующему пользователю меняется только роль, пароль сохраняется. Другой вариант — задать `ADMIN_EMAIL` и `ADMIN_PASSWORD` (8–256 символов): при запуске будет создан администратор, если такого email ещё нет. Существующие аккаунты и пароли этот механизм не перезаписывает.

## Форма и хранение

Форма доступна из «Моих новостей» и по кнопке «Предложить новость» на главной. Обязательны категория, заголовок (3–160 символов) и текст (10–20 000). Дополнительно: обложка JPG/PNG/WebP до 5 МБ и 20 мегапикселей, дата события по Уфе (UTC+5), место и HTTP(S)-ссылка на регистрацию.

Пользовательский HTML экранируется, переносы строк сохраняются. Форма, вход, регистрация, выход и действия модерации защищены CSRF-токенами. Выход и решения модерации принимаются только через POST. Неопубликованные страницы и обложки доступны только автору и администратору; другим возвращается 404.

По умолчанию локально используется `instance/uusttimes.sqlite3`. Модели `User` и `News` хранятся в таблицах `users` и `news_items`; имя `NewsItem` сохранено как совместимый псевдоним. На сервере можно задать `DATABASE_URL` для PostgreSQL. Префиксы `postgres://` и `postgresql://` автоматически переводятся в `postgresql+psycopg://`, чтобы использовать установленный драйвер psycopg 3.

Начальная схема создаётся автоматически. Для существующей схемы из `emil` выполняется добавление новых полей без удаления таблиц и записей. Старое значение `approved` становится `published`, дата публикации восстанавливается из `reviewed_at` или `created_at`; ID, пользователи, пароли, авторы и решения сохраняются. Это ограниченное обновление для данного объединения, а не универсальная система миграций. Для следующих изменений схемы следует использовать отдельные миграции.

Файл раннего анонимного прототипа `instance/uusttimes.db` не удаляется и больше не является рабочей БД. В момент объединения обе локальные базы были пустыми; резервные копии исходных файлов находятся в `instance/integration-backup-.../`. На сервере действующие записи из таблицы `news_items` сохраняются при обновлении схемы. Если отдельно переносите непустую старую таблицу `news` анонимного прототипа, нужен явный импорт и выбор авторов — автоматического назначения её записей чужим аккаунтам нет.

Обложки проверяются по содержимому, приводятся к WebP и получают случайные имена. Содержимое сохраняется в БД, локальная копия — в `instance/uploads/` или `UPLOAD_FOLDER`. Благодаря копии в БД обложки доступны и после потери локального кеша. Временные метки хранятся в UTC и отображаются по Уфе.

База и локальные данные исключены из Git. Для стабильных сессий задайте `SECRET_KEY`; локально при пустом значении создаётся и повторно используется `instance/.secret_key`.

## Страницы

| Адрес | Назначение |
| --- | --- |
| `/` | Общая лента опубликованных новостей |
| `/register`, `/login` | Регистрация и вход |
| `/logout` | Выход, только POST |
| `/my-news` | Собственные новости и их статусы, требуется вход |
| `/news/new` | Полная форма предложения новости, требуется вход |
| `/submit` | Совместимый адрес формы из `emil` |
| `/news/<id>` | Полный текст или закрытый предпросмотр |
| `/news/<id>/cover` | Обложка с проверкой доступа |
| `/news/<id>/reaction` | Добавить, заменить или снять реакцию, только POST после входа |
| `/news/<id>/delete` | Удаление опубликованной новости, только POST администратора с подтверждением |
| `/moderation` | Очередь заявок, только для администратора |
| `/support` | Поддержка разработчиков |

Лента, «Мои новости» и очередь модерации показывают по 10 записей. Страницы переключаются параметром `?page=2`. В ленте новые публикации идут первыми, в модерации — сначала старые заявки. При запросе номера больше последнего открывается последняя доступная страница.

## Категории и постоянные новости

Главная `/` по умолчанию показывает опубликованные новости **всех категорий**, по 10 на страницу. Кнопки над лентой включают фильтр: `/?category=science`. Переход между страницами сохраняет выбранную категорию; «Все новости» сбрасывает фильтр. Категория выбирается и в форме отправки. Правила модерации сохраняются.

| Код | Название |
| --- | --- |
| `study` | Учёба |
| `science` | Наука |
| `culture` | Культура |
| `sport` | Спорт |
| `career` | Карьера |
| `dorm` | Общежития |

Исходная подборка находится в `permanent.md`: 11 новостей, 9 изображений из `static/images/`; у №7 и №9 обложки нет. Файл включается в Git вместе с изображениями. При запуске приложение добавляет отсутствующие ID в рабочую БД со статусом `published`, автор — «Редакция The UUST Times». Для связи с таблицей пользователей создаётся служебная запись с зарезервированным адресом `.invalid` и случайным неизвестным паролем; прав администратора у неё нет. Подборка доступна гостям сразу, регистрации для чтения нет.

У каждой новости постоянный заголовок-ID `## news-001`, затем поля `title`, `category`, необязательные `image`, `link`, `location`; после строки `---` — обычный текст. Путь `image` задаётся относительно `static`, например `images/image_1.png`. Пустое поле означает отсутствие обложки. В исходниках не было дат публикации: сохраняется время первого импорта, повторный запуск его не меняет. Даты событий из текста автоматически не угадываются.

Добавляйте новые блоки с новыми ID (`news-012` и далее) и перезапускайте приложение. Уникальный `seed_key` в БД предотвращает дубликаты. Изменение текста в Markdown не перезаписывает уже загруженную запись автоматически; для явного обновления:

```powershell
.\.venv\Scripts\python.exe -m flask --app app import-news --update
```

Команда обновляет текст, категорию, ссылку, место и обложку только записей с соответствующими ID. Их даты, авторы и решения модерации сохраняются; обычные пользовательские новости не затрагиваются. Удаление блока из Markdown не удаляет запись из БД. Обложки проходят те же проверки и преобразование в WebP, что и пользовательские, и сохраняются в БД. Исходные PNG остаются в `static`.

Удаление через сайт очищает заголовок, текст, обложку в БД, ссылки и данные события, удаляет реакции и локальный кеш обложки. В БД остаётся служебная запись со статусом `deleted`, прежним ID и `seed_key`: адрес не будет принадлежать другой новости, а подборка не восстановит удалённую публикацию при запуске или `import-news --update`. Страница и обложка возвращают 404 всем, включая автора и администратора; запись не видна в общей ленте и «Моих новостях». Исходные файлы Markdown и PNG в репозитории не изменяются.

Существующая схема дополняется полями `category`, `seed_key`, `external_url` и индексами. Ранее созданным новостям присваивается `study` («Учёба»); записи, аккаунты и статусы сохраняются. В автоматических тестах загрузка подборки отключена по умолчанию (`SEED_NEWS=False`); тесты импорта включают её отдельно.

## Реакции

На опубликованных новостях доступны 👍, ❤️, 🔥, 😮 и 😢. Гости видят счётчики и ссылку на вход. Авторизованный пользователь выбирает одну реакцию на новость: другая кнопка заменяет выбор, повторное нажатие выбранной снимает реакцию. Кнопки есть в общей ленте, категориях, опубликованных «Моих новостях» и на странице материала. Счётчики обновляются без перезагрузки; без JavaScript работает обычная POST-форма с возвратом к новости и сохранением страницы/категории.

Таблица `news_reactions` создаётся при запуске. Составной первичный ключ `(news_id, user_id)` обеспечивает одну реакцию аккаунта на новость, `CHECK` ограничивает набор кодов. Все изменения проходят CSRF-проверку и проверку входа; к `pending` и `rejected` реакцию нельзя добавить даже автору или администратору. Клиент не задаёт пользователя: сервер берёт ID из сессии. Реакции сохраняются после перезапуска. Счётчики для всей страницы загружаются общим запросом, свой выбор — ещё одним запросом.

## Настройки и поддержка

| Переменная | Значение |
| --- | --- |
| `SECRET_KEY` | Постоянный случайный секрет подписи сессий; задайте на сервере |
| `DATABASE_URL` | PostgreSQL или другой SQLAlchemy URL; пусто — локальная SQLite |
| `DONATION_URL` | Публичная HTTPS-ссылка платёжного сервиса |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Необязательное создание первого администратора |
| `UPLOAD_FOLDER` | Необязательный путь к локальному кешу обложек |

Для кнопки поддержки укажите публичную ссылку сервиса, например CloudTips, в `.env` или окружении. Карту привязывают в личном кабинете платёжного сервиса. Реквизиты карты, пароли и ключи в код или Git не добавляйте. Без ссылки или при неверном формате страница сообщает, что ссылка на оплату временно недоступна. Доступность самого платёжного сервиса приложение не проверяет.

Сумма, способ оплаты, подтверждение и история переводов находятся на стороне сервиса. Нажатие кнопки или возврат на сайт не считаются подтверждением перевода; локального счётчика платежей и вебхуков нет. `.env` исключён из Git, `.env.example` содержит только образец.

## Структура и проверки

`uusttimes/auth.py` содержит аккаунты; `news.py` — отправку и модерацию; `routes.py` — ленту, собственные материалы и просмотр; `forms.py` — формы; `models.py` — модели; `schema.py` — обновление прежней схемы; `pagination.py` — общий механизм страниц; `uploads.py` — изображения. Новые страницы наследуют `base.html` и используют блоки `title`, `description`, `styles`, `content`, `scripts`.

Стили проекта находятся в отдельных CSS. `static/css/university/` — исходный справочный образец, не изменяется и не импортируется. Внешние шрифты и фронтенд-фреймворки не требуются.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют отдельные временные базы: аккаунты, права, CSRF, модерация, обложки, пагинация, сохранность данных, обновление старой схемы и настройки. Рабочая БД не заполняется тестовыми пользователями и новостями.
