# The UUST Times

Студенческое издание УУНиТ на Flask + Jinja2: аккаунты, новости, обложки, пагинация, модерация и поддержка разработчиков. Приложение находится в корне репозитория.

## Локальный запуск

На Render используется Python 3.11.9 из `.python-version`. Локально подойдёт Python 3.11 или новее.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:8080. Вариант с автоматическим перезапуском для разработки:

```powershell
.\.venv\Scripts\python.exe -m flask --app app run --debug --port 8080
```

Скопируйте `.env.example` в `.env` на новом компьютере и заполните нужные настройки. Существующий `.env` не перезаписывайте. Файл читается автоматически при создании приложения; после изменения перезапустите сервер. Переменные окружения имеют приоритет над `.env`, явная тестовая конфигурация — над обоими источниками.

## Пользователи и публикация

- Гость читает опубликованные новости и может зарегистрироваться или войти.
- Пользователь `member` отправляет материал на проверку. Новость получает `pending` и видна только автору и администраторам.
- Администратор `admin` проверяет очередь: публикует (`published`) или отклоняет (`rejected`) с обязательной причиной.
- Свои новости администратор публикует сразу. В записи сохраняются автор, проверяющий и время публикации; дополнительное одобрение не требуется.
- «Мои новости» привязаны к аккаунту, работают в разных браузерах после входа и показывают статус и причину отклонения.
- Изменение ролей через форму регистрации или отправку новости невозможно: роль нового аккаунта всегда `member`, автора и статус назначает сервер.

Первого администратора можно создать или назначить существующему аккаунту:

```powershell
.\.venv\Scripts\python.exe -m flask --app app create-admin admin@example.com
```

Для нового аккаунта команда запросит пароль без вывода на экран. Существующему пользователю меняется только роль, пароль сохраняется. Другой вариант — задать `ADMIN_EMAIL` и `ADMIN_PASSWORD` (8–256 символов): при запуске будет создан администратор, если такого email ещё нет. Существующие аккаунты и пароли этот механизм не перезаписывает.

## Форма и хранение

Форма доступна из «Моих новостей» и по кнопке «Предложить новость» на главной. Обязательны заголовок (3–160 символов) и текст (10–20 000). Дополнительно: обложка JPG/PNG/WebP до 5 МБ и 20 мегапикселей, дата события по Уфе (UTC+5), место и HTTP(S)-ссылка на регистрацию.

Пользовательский HTML экранируется, переносы строк сохраняются. Форма, вход, регистрация, выход и действия модерации защищены CSRF-токенами. Выход и решения модерации принимаются только через POST. Неопубликованные страницы и обложки доступны только автору и администратору; другим возвращается 404.

По умолчанию локально используется `instance/uusttimes.sqlite3`. Модели `User` и `News` хранятся в таблицах `users` и `news_items`; имя `NewsItem` сохранено как совместимый псевдоним. На сервере можно задать `DATABASE_URL` для PostgreSQL. Префиксы `postgres://` и `postgresql://` автоматически переводятся в `postgresql+psycopg://`, чтобы использовать установленный драйвер psycopg 3.

Начальная схема создаётся автоматически. Для существующей схемы из `emil` выполняется добавление новых полей без удаления таблиц и записей. Старое значение `approved` становится `published`, дата публикации восстанавливается из `reviewed_at` или `created_at`; ID, пользователи, пароли, авторы и решения сохраняются. Это ограниченное обновление для данного объединения, а не универсальная система миграций. Для следующих изменений схемы следует использовать отдельные миграции.

Файл раннего анонимного прототипа `instance/uusttimes.db` не удаляется и больше не является рабочей БД. В момент объединения обе локальные базы были пустыми; резервные копии исходных файлов находятся в `instance/integration-backup-.../`. На сервере действующие записи из таблицы `news_items` сохраняются при обновлении схемы. Если отдельно переносите непустую старую таблицу `news` анонимного прототипа, нужен явный импорт и выбор авторов — автоматического назначения её записей чужим аккаунтам нет.

Обложки проверяются по содержимому, приводятся к WebP и получают случайные имена. Содержимое сохраняется в БД, локальная копия — в `instance/uploads/` или `UPLOAD_FOLDER`. Благодаря копии в БД обложки доступны и после потери локального кеша. Временные метки хранятся в UTC и отображаются по Уфе.

База и локальные данные исключены из Git. Для стабильных сессий задайте `SECRET_KEY`; локально при пустом значении создаётся и повторно используется `instance/.secret_key`.

## Страницы

| Адрес | Назначение |
| --- | --- |
| `/` | Общая лента опубликованных новостей |
| `/register`, `/login` | Регистрация и вход |
| `/logout` | Выход, только POST |
| `/my-news` | Собственные новости и их статусы, требуется вход |
| `/news/new` | Полная форма предложения новости, требуется вход |
| `/submit` | Совместимый адрес формы из `emil` |
| `/news/<id>` | Полный текст или закрытый предпросмотр |
| `/news/<id>/cover` | Обложка с проверкой доступа |
| `/moderation` | Очередь заявок, только для администратора |
| `/support` | Поддержка разработчиков |

Лента, «Мои новости» и очередь модерации показывают по 10 записей. Страницы переключаются параметром `?page=2`. В ленте новые публикации идут первыми, в модерации — сначала старые заявки. При запросе номера больше последнего открывается последняя доступная страница.

## Настройки и поддержка

| Переменная | Значение |
| --- | --- |
| `SECRET_KEY` | Постоянный случайный секрет подписи сессий; задайте на сервере |
| `DATABASE_URL` | PostgreSQL или другой SQLAlchemy URL; пусто — локальная SQLite |
| `DONATION_URL` | Публичная HTTPS-ссылка платёжного сервиса |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Необязательное создание первого администратора |
| `UPLOAD_FOLDER` | Необязательный путь к локальному кешу обложек |

Для кнопки поддержки укажите публичную ссылку сервиса, например CloudTips, в `.env` или окружении. Карту привязывают в личном кабинете платёжного сервиса. Реквизиты карты, пароли и ключи в код или Git не добавляйте. Без ссылки или при неверном формате страница сообщает о подготовке приёма донатов.

Сумма, способ оплаты, подтверждение и история переводов находятся на стороне сервиса. Нажатие кнопки или возврат на сайт не считаются подтверждением перевода; локального счётчика платежей и вебхуков нет. `.env` исключён из Git, `.env.example` содержит только образец.

## Render

Root Directory сервиса — корень репозитория (пустое значение или `.`), а не `uust_times-main`. Build Command: `pip install -r requirements.txt`. Start Command:

```sh
gunicorn app:app --bind 0.0.0.0:$PORT
```

В окружении сервиса задайте `DATABASE_URL` и постоянный `SECRET_KEY`, при необходимости — настройки администратора и ссылку поддержки. `gunicorn` и `psycopg[binary]` включены в зависимости. Объединение проверяется локально; само по себе оно не меняет настройки сервиса и не выполняет развёртывание.

## Структура и проверки

`uusttimes/auth.py` содержит аккаунты; `news.py` — отправку и модерацию; `routes.py` — ленту, собственные материалы и просмотр; `forms.py` — формы; `models.py` — модели; `schema.py` — обновление прежней схемы; `pagination.py` — общий механизм страниц; `uploads.py` — изображения. Новые страницы наследуют `base.html` и используют блоки `title`, `description`, `styles`, `content`, `scripts`.

Стили проекта находятся в отдельных CSS. `static/css/university/` — исходный справочный образец, не изменяется и не импортируется. Внешние шрифты и фронтенд-фреймворки не требуются.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют отдельные временные базы: аккаунты, права, CSRF, модерация, обложки, пагинация, сохранность данных, обновление старой схемы и настройки. Рабочая БД не заполняется тестовыми пользователями и новостями.
